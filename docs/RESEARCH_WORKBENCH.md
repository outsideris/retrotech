# 문단별 추가 조사 리더

기존 로컬 HTML의 본문을 읽으면서 문단별로 질문하고, 원자료를 확인한 보충 내용을 같은 위치에 쌓는다. 공개 사이트·RSS·에피소드 대본과 별개인 로컬 도구다.

## 실행

Go 1.26.2 이상으로 **지속되는 경로**에 바이너리를 만든다. `cmd/build`는 `dist`를 정리하므로 연구 바이너리는 `dist` 밖에 둔다.

```sh
mkdir -p .local-bin
go build -o .local-bin/retrotech-research ./cmd/research
.local-bin/retrotech-research -report '/absolute/path/to/report'
```

보고서 폴더에 짝이 맞는 `index.html`과 `research.md`가 있어야 한다. 현재 RetroTech HTML의 `<article class="prose">` 구조와 Markdown 문단을 대응한다. 임의의 웹페이지를 변환하는 기능은 아니다. 경로에 `episodes`가 있으면 거부한다.

첫 실행은 원본을 `.research/base.html`, `.research/base.md`에 보존하고 UI를 HTML에 삽입한다. 폴더의 `start-research.command`를 실행하면 연결 프로그램만 시작한다. **새 브라우저 창을 열지 않는다.** `index.html`을 파일로 열어 둔 채 오른쪽 사이드바에서 바로 질문할 수 있다. 실행 터미널은 열어 두어야 하며, 닫거나 컴퓨터를 재시작하면 연결 프로그램을 다시 실행해야 한다. 서버 없이 HTML을 열어도 본문과 저장된 추가 내용은 읽을 수 있다.

기본 포트는 `49327`이고 점유 중이면 운영체제가 빈 포트를 고른다. `-port 0`으로 처음부터 자동 배정할 수 있다. `7800–7899`는 terrarium 예약 대역이라 거부한다. `127.0.0.1`에만 바인딩하며 상시 서비스로 등록하지 않는다.

## 읽기와 조사

1. `start-research.command`를 실행하고 기존 `index.html`을 연다. 사이드바의 **연결됨** 표시를 확인한 뒤 문단을 클릭하거나 장을 고른다.
2. 질문·모델·깊이를 선택하고 **조사하기**를 누른다. 보고서당 한 건씩 실행한다.
3. 결과는 해당 문단 뒤에 **추가 조사**로 저장된다. 질문, 날짜, 모델, 근거 위치와 출처가 함께 남고 정정이면 별도 표시된다. 결과가 도착해도 본문 위치를 유지한다.
4. **원래 장면**, **본문의 추가 내용**, **이어서 질문**으로 이동한다. 대화는 기본적으로 선택한 장만 보여 주며 전체 보기로 바꿀 수 있다.
5. **추가 내용** 탭에서 본문에 보일 항목을 숨기거나 복원한다. 조사 기록은 삭제하지 않는다.
6. 충분히 읽고 정리한 뒤 **스킬에 남길 점**에서 규칙 초안을 편집·선택하고 반영한다. `references/follow-up-learnings.md`에 일반화된 점검 질문이 쌓이고 SKILL.md가 이를 연결한다. 스킬 변경 전 사본은 `.research/skill-backups`에 보관한다. 동일 규칙은 중복 저장하지 않는다.

## 모델과 로그인

- 기본: **Codex GPT-6.1 Sol / high**. 원자료를 대조하고 이야기의 빈틈을 채우는 질문에 사용한다.
- 짧은 사실·날짜 확인: **Sol / medium**. 출처 확인 기준은 동일하다. 목록에 더 빠른 codex 모델을 두지 않아 같은 Sol의 깊이만 낮춘다.
- 상충하는 증언·메일 스레드·이전 버전 설계의 복원: **Sol / xhigh**.
- Sol / xhigh로도 결론이 서지 않는 가장 까다로운 질문: **GPT-6 Astra / medium**, 필요하면 high. 공식 안내는 Astra를 Light(low)부터 시작하라고 권하지만 이 리더에는 low가 없다.
- Claude 대안: **Sonnet 5.5 / high**. 더 까다로운 질문은 **Opus 5.5 / high 또는 xhigh**.
- 깊이는 medium·high·xhigh만 둔다. low는 출처 대조에 얕다. max는 Claude 문서가 과잉 사고(overthinking)를 경고한다. codex의 ultra는 하위 에이전트에 작업을 나누는데, 이 리더는 하위 에이전트를 끄고 실행한다. GPT-6.1 Sol은 CLI 기본 깊이가 low이고 공식 안내는 기본값에서 시작하라고 하지만, 같은 안내가 여러 출처를 대조하는 일에는 High·Extra High를 권하므로 이 리더는 medium부터 둔다.
- 두지 않는 모델: **Fable 5.1**은 요금제에 따라 사용 크레딧으로 청구될 수 있고 `-p` 실행에서는 그때 동의를 묻지 않으므로, 정액 구독을 전제로 한 이 리더에 맞지 않는다. **GPT-6 Luna**는 요약·추출 같은 대량 작업용 효율 모델이다. **Haiku 5.5**는 빠른 답을 위한 가장 작은 모델이다. **GPT-6.1 Terra**는 2026-10-29에 Assist 카탈로그에 들어왔지만, 공식 안내가 조사가 아니라 글쓰기·시각 자료·컴퓨터 사용용으로 소개해 두지 않았다. 짧은 사실 확인을 Terra로 돌릴지는 따로 정할 큐레이션 결정이다. 이전 세대(GPT-6 Sol, GPT-5.6, Opus 5·Sonnet 5)도 뺐다.
- 이 추천은 작업 성격에 따른 선택이며 실제 품질·소요 시간은 질문에 따라 다르다.

앱은 설치된 `codex`·`claude` 실행 파일을 찾고 기존 CLI 인증을 사용한다. API 키를 읽거나 저장하지 않는다. 사용자가 터미널에서 `codex login` 또는 `claude auth login`으로 로그인한다. 구독·모델 접근 권한은 각 CLI 계정에 따른다. 모델 목록은 2026-09-30의 공식 안내와 claude 2.1.284·codex 0.159.0을 기준으로 2026-09-16 목록에서 갱신했다. Astra는 9/16에 제외했다가 2026-09-30 사용자 결정으로 가장 까다로운 질문용으로 추가했다. 2026-10-29에 기본을 GPT-6 Sol에서 **GPT-6.1 Sol**로 바꿨다(codex 0.160.0). OpenAI는 GPT-6.1 Sol을 GPT-6 Sol의 업그레이드로 내놓았다. 의도적으로 어렵게 고른 프롬프트에서 사실 오류가 든 답의 비율이 낮고(low 깊이에서 11.4% → 7.7%), 검색 도구가 작동하지 않을 때 이를 알리지 않은 비율도 4.9%에서 2.1%로 낮다(실패를 유도한 평가, 최대 깊이). API 가격은 같다. 계정 카탈로그는 GPT-6 Sol을 "Previous generation"으로 표시하고, 공식 모델 안내의 추천 모델과 설정 예시에는 GPT-6 Sol 대신 GPT-6.1 Sol이 있다. 9/30에 GPT-5.6 Sol을 GPT-6 Sol로 바꿨을 때처럼 이전 세대는 함께 두지 않고 교체했다.

목록을 바꿀 때는 CLI를 먼저 올리고 Assist 카탈로그(`internal/editor/assist/catalog.go`)를 갱신한 뒤 이 목록을 고친다. 목록의 원본은 `internal/editor/assist/research.go`의 `researchModels`·`researchEfforts` 한 곳이며 서버의 요청 검증도 이것을 쓴다. 카탈로그에 없는 모델은 테스트가 거부한다. 사이드바 메뉴(`internal/research/assets/panel.html`)는 정적 HTML이라 함께 고치며, 둘이 어긋나면 `go test`가 실패한다. 그다음 로그인된 제공자로 보고서 사본에서 모델마다 실제 조사를 한 번 확인하고 `.local-bin/retrotech-research`를 다시 빌드한다. 이미 저장된 추가 조사는 답한 모델의 이름을 그대로 유지하며, 새 요청만 목록으로 검사한다.

## 저장과 오류 처리

- `.research/state.json`: 질문, 상태, 결과, 출처, 숨김 여부, 반영한 규칙. 보고서와 함께 폴더 전체를 백업한다.
- `.research/jobs/<id>/`: 구조화 출력 스키마와 CLI 결과. 기존 대화 세션을 이어 쓰는 대신 본문과 관련된 이전 조사 최대 4건을 매 요청에 전달한다.
- HTML·Markdown은 보존된 원문과 표시할 추가 항목에서 다시 생성한다. 원문은 수정하지 않는다. **정정**도 출처와 함께 별도 블록으로 읽는다.
- 다른 프로그램이 HTML 또는 Markdown을 수정하면 해시 충돌로 저장을 중단한다. 외부 변경을 덮어쓰지 않는다. 수동 본문 재편집 후 기존 조사 앵커를 옮기는 기능은 없다. 먼저 폴더를 복사해 보존하고, 새 본문은 새 보고서 폴더로 시작한다.
- 일반적인 쓰기 실패에서는 직전 HTML·Markdown 쌍을 복구한다. 쓰기 도중 프로세스·전원이 강제 종료되어 상태와 파일이 어긋나면 자동 덮어쓰기 대신 충돌로 중단한다. `.research/base.*`와 상태·백업을 확인해 복구해야 한다.
- 완료 결과를 저장하지 못하면 `.research/unsaved-<id>.json`에 결과를 별도로 남긴다. 서버 재시작 시 중단된 요청은 실패로 표시하며 질문을 다시 작성할 수 있다.
- 조사 제한은 20분이다. 취소 시 CLI 프로세스를 종료한다. 출력 스키마가 잘못되면 본문에 넣지 않고 실패 사유를 표시한다.

## 구조와 접근 범위

`cmd/research` → `internal/research`(HTTP·상태·앵커·HTML/Markdown 렌더·스킬 반영) → `internal/editor/assist/research.go`(CLI). 브라우저 UI는 Go 바이너리에 임베드되고 보고서에 인라인으로 들어간다. 새 런타임 패키지 의존성은 없다.

Codex는 `exec`, 읽기 전용 샌드박스, 실시간 웹 검색, 임시 세션, 구조화 출력으로 호출한다. 셸·앱·하위 에이전트를 비활성화한다. Claude는 구독 인증을 유지하는 safe mode와 WebSearch/WebFetch만 사용한다. CLI의 쓰기 도구에 HTML이나 스킬을 맡기지 않는다. 결과의 텍스트와 URL을 검증·이스케이프한 후 앱이 고정 경로에 기록한다.

HTTP는 보고서와 지정 API만 제공한다. Host를 검증하고 변경 요청은 JSON·전용 헤더를 요구한다. 같은 Origin에서 사용하거나, 파일 페이지(`Origin: null`)가 보고서별 연결 토큰을 보낼 때만 API 연결을 허용한다. 파일 페이지의 CORS preflight는 API 경로에 한정하며 실제 요청마다 토큰을 검사한다. 외부 웹사이트 Origin에는 허용하지 않는다. 연결 토큰은 `.research/browser-token`과 로컬 HTML에만 보관하고 URL·로그에 넣지 않는다. 임의 파일 읽기·셸 명령·모델 이름을 API로 받지 않는다. 스킬 반영은 사용자의 선택 버튼으로만 실행하며, 주제별 사실을 공통 규칙으로 자동 승격하지 않는다.

## 연결이 안 될 때

- 사이드바는 최초 연결과 연결 끊김을 구분해 표시하고 5초마다 다시 연결한다. **지금 다시 연결**로 즉시 재시도할 수 있다. 연결이 돌아오면 같은 화면에서 계속하며 질문 초안·선택 문단·본문 위치를 유지한다.
- 서버가 꺼져 있으면 `start-research.command`를 실행한다. HTML 자체에는 임의의 로컬 프로그램을 실행할 권한이 없으므로 브라우저만으로 꺼진 CLI 연결 프로그램을 시작할 수는 없다.
- 브라우저가 로컬 네트워크 접근 허용을 요청하면 이 보고서에 허용한다. 파일 URL의 출처 처리는 Chrome에서 검증했다.
- 업데이트 전 HTML을 이미 열어 둔 경우 한 번 새로 고친다. 모델 목록이 바뀐 뒤 예전 메뉴로 보내면 "지원하지 않는 조사 모델입니다"가 표시되며, 새로 고치면 해결된다. 다른 프로그램이 포트를 차지해서 서버가 새 포트로 시작한 경우에도 생성된 HTML을 새로 고치면 새 주소를 사용한다.
- 2026-09-24 수정 전에는 파일로 열면 채팅 연결을 건너뛰고 다른 주소로 이동하게 했다. 현재 버전은 파일 HTML에서 직접 연결한다. 기존 서버가 종료된 상태라면 수정 여부와 별개로 다시 실행해야 한다.
