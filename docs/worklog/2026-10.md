### 18:53 — 배포 알림을 terrarium 수신함을 거쳐 Chime 으로 보냄

- Summary: 빌드 래퍼 `scripts/cf-build.sh` 의 배포 알림을 Cloudflare Worker `cf-webhook` 대신 terrarium 의 공개 수신함(`POST /in/chime`)으로 보내게 했다. 인증은 URL 의 `?token=` 에서 `Authorization: Bearer` 로, 본문은 Chime 의 알림 필드로 바꿨다.
- Context: 사용자 요청 — terrarium 에 공개 웹훅 엔드포인트가 생겼으니 메시지 포맷은 chime 프로젝트를 따라 그쪽으로 보내 달라. 확인한 계약: terrarium `docs/DEPLOY.md` 16장·`cloudflare/inbox/README.md`·`src/core/inbox/contract.ts`(주소는 대상만 말하는 `/in/<service>`, 대상의 비밀을 Bearer·`cf-webhook-auth`·`x-hub-signature-256` 중 하나로 낸다, 본문 64 KiB, 큐에 넣은 뒤 `200`), chime `docs/SENDING.md`·`docs/TERRARIUM.md`·`terrarium.json`(수신함이 `/notify` 로 넘긴다)·`src/adapters/generic.ts`·`src/format.ts`.
- 결정:
  - 환경변수를 둘로 나눴다 — `DEPLOY_WEBHOOK_URL`(수신함 주소)·`DEPLOY_WEBHOOK_TOKEN`(수신함 비밀). 수신함은 헤더로만 인증하므로 비밀을 URL 에 둘 수 없다. 둘 중 하나라도 없으면 알림을 건너뛴다(비밀 없이 보내면 늘 `401` 이다).
  - `status` 는 `failure` 대신 Chime 의 표준값 `failed`, `level` 은 성공 `info`·실패 `warn`(직전 배포가 유지되므로 `critical` 이 아니다). `title` 은 생략해 Chime 의 배포 제목을 쓴다.
  - `environment`(`main` → `production`, 그 밖 → `preview`)와 `commitMessage`(`git log -1 --pretty=%s`)를 더했다. 브랜치 이름·커밋 제목은 JSON 이스케이프한다 — 이전에는 값을 그대로 끼워 넣어 따옴표가 든 값이 본문을 깨뜨릴 수 있었다.
  - `url` 은 성공했을 때만 보낸다(실패한 배포의 주소는 죽은 링크다). `timestamp` 는 보내지 않는다(채널이 시각을 보여 준다).
  - `Idempotency-Key` 는 보내지 않는다 — 래퍼가 재시도하지 않고, 수신함이 이벤트 id 로 붙인다. 커밋 SHA 로 키를 만들면 같은 커밋의 재배포가 다른 본문(`url`)으로 `409` 가 된다.
  - `curl` 에 `--max-time 15` 를 줬다 — 알림이 빌드를 붙잡지 않게.
